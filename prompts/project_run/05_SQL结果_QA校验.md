# 05 SQL 结果 QA 校验

请只执行本阶段。优先读取 SQL 流水线本次 run.json；预览状态、旧运行和 tables.partial 不能证明 SQL 跑通或 QA 通过。

任务：

1. 生成或检查 `sql/04_checks/` 中的校验 SQL。
2. 校验 ODS、DWD、ADS 表的行数、主键唯一性、缺失、重复、异常标记和指标汇总一致性。
3. 输出 `outputs/reports/qa_report.md`。
4. 如果发现问题，说明问题表、问题字段、可能原因和修复建议。
5. 明确哪些 ADS 表适合导入 Power BI。

规则：

- 不允许只说“结果正常”，必须列出校验项。
- 不允许用未运行的 SQL 结果编造结论。
- 如果需要用户导出校验结果，必须明确导出步骤。

自动校验约定：

- 将业务校验写成明确的 SELECT 查询并注册到 `config.local.yaml` 的 checks；zero_rows 返回零异常行才通过，scalar_equals 必须返回一行一列并等于期望值。
- 自动执行入口已包含校验；检查本次 run.json 中所有校验步骤，不重复手动运行。
- 原先只有行数/金额展示的查询需要改写为可判定的异常行/差额查询；不能因 SQL 未报错就宣布业务正确。
- 有异常时停止后续交付，不拿上次导出表替代；修复后先核实部分执行状态和重新运行方案。
- 成功表从本次 `outputs/runs/<run_id>/tables/` 取得；只有额外业务证据确实缺失时才请求本地查询，数据和报错先脱敏。
