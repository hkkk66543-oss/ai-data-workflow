# 05 SQL 结果 QA 校验

请只执行本阶段。执行前必须确认 SQL 已在 Navicat / MySQL 中跑通。

任务：

1. 生成或检查 `sql/04_checks/` 中的校验 SQL。
2. 校验 ODS、DWD、ADS 表的行数、主键唯一性、缺失、重复、异常标记和指标汇总一致性。
3. 输出 `outputs/reports/qa_report.md`。
4. 如果发现问题，说明问题表、问题字段、可能原因和修复建议。
5. 明确哪些 ADS 表适合导入 Power BI。

规则：

- 不允许只说“结果正常”，必须列出校验项。
- 不允许用未运行的 SQL 结果编造结论。
- 如果需要用户导出校验结果，必须明确导出步骤。

如需用户在 Navicat 中运行 CHECKS SQL，必须输出：

```text
【需要你手动操作】
操作目标：运行 sql/04_checks/ 中的校验 SQL 并反馈结果。
为什么需要你操作：校验 SQL 需要在你的 MySQL 数据库中读取真实结果。
具体步骤：
1. 打开 Navicat 查询窗口。
2. 打开 sql/04_checks/ 中的校验 SQL 文件。
3. 点击运行。
4. 查看每个结果集的行数、异常数、指标差异。
5. 如需保存结果，右键结果表格导出为 CSV，保存到 outputs/tables/。
完成后你应该看到：每个校验 SQL 都返回结果，异常项可被定位。
如果报错怎么办：复制完整报错和出错 SQL 文件名给 Codex。
完成后请回复我什么：请回复“CHECKS 已运行”并粘贴异常结果，或回复“无异常”。
```

阶段结束时必须输出：

```text
下一步是否需要你手动操作：
如果需要，具体操作是什么：
操作完成后，请回复我什么：
```
