# 03 确认计划：生成 SQL

请只执行本阶段。执行前必须确认用户已经认可 `docs/执行计划.md` 和 `docs/指标口径.md`。

任务：

1. 基于真实字段生成 MySQL 8.0 SQL。
2. SQL 文件按分层保存：
   - `sql/01_ods/`
   - `sql/02_dwd/`
   - `sql/03_ads/`
   - `sql/04_checks/`
3. 表名和字段名默认使用简约中文，并用反引号包裹。
4. 所有表和字段必须加中文注释。
5. 生成或更新 `docs/SQL中文命名规范.md`。
6. 生成或更新 `docs/SQL中英文命名映射表.md`。

命名规则：

- ODS：`原始_事件表`、`原始_订单表`、`原始_用户表`
- DWD：`清洗_事件明细`、`清洗_订单明细`、`清洗_用户画像`
- DIM：`维度_设备`、`维度_地区`、`维度_产品`
- ADS：`应用_每日概览`、`应用_用户分层`、`应用_渠道分析`
- CHECK：`校验_数据质量明细`、`校验_指标汇总`

字段示例：

- user_id -> `用户编号`
- session_id -> `会话编号`
- event_type -> `事件类型`
- event_time -> `事件时间`
- total_users -> `用户数`
- abnormal_rate -> `异常率`

SQL 生成后必须说明：

- 生成了哪些中文表。
- 每张中文表对应什么业务含义。
- 每张表由哪些原始字段加工而来。
- 哪些字段是清洗字段。
- 哪些字段是异常标记字段。
- 哪些表适合导入 Power BI。

如果需要用户在 Navicat / MySQL 中运行 SQL，必须输出：

```text
【需要你手动操作】
操作目标：在 Navicat / MySQL 中按分层运行 SQL。
为什么需要你操作：Codex 可以生成 SQL 文件，但不能替你在本地 Navicat 中确认连接、创建数据库和执行 SQL。
具体步骤：
1. 打开 Navicat，连接 MySQL。
2. 新建数据库，字符集选择 utf8mb4，排序规则选择 utf8mb4_general_ci 或 utf8mb4_0900_ai_ci。
3. 打开查询窗口。
4. 先运行 sql/01_ods/ 中的 SQL。
5. 再运行 sql/02_dwd/ 中的 SQL。
6. 再运行 sql/03_ads/ 中的 SQL。
7. 最后运行 sql/04_checks/ 中的 SQL。
8. 每运行完一层，检查是否有报错和表是否创建成功。
完成后你应该看到：数据库中出现原始、清洗、应用和校验层中文表。
如果报错怎么办：复制完整报错、出错 SQL 文件名和出错语句给 Codex，然后使用 04_SQL报错修复.md。
完成后请回复我什么：请回复“SQL 已运行完成”或粘贴完整 SQL 报错。
```
