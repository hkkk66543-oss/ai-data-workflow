# 04 SQL 报错修复

请只执行本阶段。优先读取本次失败运行的 `outputs/runs/<run_id>/run.json`，结合错误类型、MySQL errno/sqlstate、SQL 文件及语句序号定位；也接受脱敏的 Navicat 报错。

任务：

1. 读取报错 SQL 文件。
2. 分析 MySQL 8.0 报错原因。
3. 修复 SQL，并保持中文表名和字段名使用反引号。
4. 如果中文物理表名导致兼容问题，提供英文物理表 + 中文视图的备选方案。
5. 更新 `docs/SQL中英文命名映射表.md`。
6. 说明修改原因和需要重新运行的 SQL 文件。

规则：

- 不允许删除已有 SQL 分层结构。
- 不允许改动与报错无关的业务逻辑。
- 不允许通过虚构字段绕过报错。
- 所有字段必须来自真实数据或已确认加工逻辑。

临时模式修复后核实上次实例已清理，重新预览并在新的临时实例执行；保留前次 SQL 与失败报告。existing 模式必须先核实已提交步骤/DDL 的数据库状态和重跑方案。不能通过去掉校验或无限重试绕过错误。

若当前环境没有临时运行条件，说明缺少的执行依赖，使用支持该模式的执行环境；仅 existing 模式确实无法连接时才交接用户本机运行。

如果需要，具体操作是什么：
操作完成后，请回复我什么：
