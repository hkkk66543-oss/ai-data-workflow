# 04 SQL 报错修复

请只执行本阶段。用户会提供 Navicat / MySQL 报错信息、出错 SQL 文件名和出错语句。

任务：

1. 读取报错 SQL 文件。
2. 分析 MySQL 8.0 报错原因。
3. 修复 SQL，并保持中文表名和字段名使用反引号。
4. 如果中文物理表名导致兼容问题，提供英文物理表 + 中文视图的备选方案。
5. 更新 `docs/SQL中英文命名映射表.md`。
6. 说明修改原因和需要重新运行的 SQL 文件。

规则：

- 不允许删除已有 SQL 分层结构。
- 不允许改动与报错无关的业务逻辑。
- 不允许通过虚构字段绕过报错。
- 所有字段必须来自真实数据或已确认加工逻辑。

修复后如果需要用户重新运行 SQL，必须输出：

```text
【需要你手动操作】
操作目标：在 Navicat / MySQL 中重新运行修复后的 SQL。
为什么需要你操作：SQL 执行需要连接你的本地数据库环境，Codex 不能直接确认 Navicat 中的执行结果。
具体步骤：
1. 打开 Navicat 的查询窗口。
2. 打开本次修复的 SQL 文件。
3. 先运行被修复文件；如它依赖前置表，按 ODS、DWD、ADS、CHECKS 顺序重新运行相关文件。
4. 查看消息窗口是否仍有报错。
5. 执行简单行数检查，确认目标表有数据。
完成后你应该看到：修复后的 SQL 成功运行，目标表或视图创建成功。
如果报错怎么办：复制完整报错、SQL 文件名和出错行附近 SQL 给 Codex。
完成后请回复我什么：请回复“SQL 修复后已跑通”或粘贴新的完整报错。
```

阶段结束时必须输出：

```text
下一步是否需要你手动操作：
如果需要，具体操作是什么：
操作完成后，请回复我什么：
```
