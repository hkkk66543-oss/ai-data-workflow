# 04 SQL 报错修复

请只执行本阶段。优先读取本次失败运行的 `outputs/runs/<run_id>/run.json`，结合错误类型、MySQL errno/sqlstate、SQL 文件及语句序号定位；也接受脱敏的 Navicat 报错。

任务：

1. 读取报错 SQL 文件。
2. 分析 MySQL 8.0 报错原因。
3. 修复 SQL，并保持中文表名和字段名使用反引号。
4. 如果中文物理表名导致兼容问题，提供英文物理表 + 中文视图的备选方案。
5. 更新 `docs/SQL中英文命名映射表.md`。
6. 说明修改原因和需要重新运行的 SQL 文件。

规则：

- 不允许删除已有 SQL 分层结构。
- 不允许改动与报错无关的业务逻辑。
- 不允许通过虚构字段绕过报错。
- 所有字段必须来自真实数据或已确认加工逻辑。

修复后必须检查上次已完成的步骤及实际数据库状态。MySQL DDL/已提交步骤不能整体回滚；原始表非空会阻止重复导入，不应直接全量重跑。先提出使用新项目库或审核后的清理方案；取得相应授权后重新预览并执行。不能通过去掉校验或无限重试绕过错误。

若当前环境无法访问本机数据库，按固定格式交接用户在本机运行入口并反馈脱敏后的 run.json，不要求用户逐段复制 SQL 或发送数据库密码。

阶段结束时必须输出：

```text
下一步是否需要你手动操作：
如果需要，具体操作是什么：
操作完成后，请回复我什么：
```
