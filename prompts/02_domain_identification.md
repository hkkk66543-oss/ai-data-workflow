# 02 Domain Identification

目标：判断当前数据属于什么行业或业务场景，并避免在行业未确认前套用固定模板。

## 如何根据数据判断行业

请基于以下证据判断：

1. 文件名和表名：例如 orders、events、loans、courses、jobs、content、campaigns。
2. 字段名：例如 user_id、order_id、loan_id、course_id、experiment_id、sku_id。
3. 样例数据：状态值、金额字段、时间字段、分类字段、文本字段。
4. 表关系：用户-事件、订单-商品、申请-还款、课程-学习、岗位-候选人等。
5. 业务含义：字段组合能否支持某类业务流程。

## 如何根据字段判断业务场景

- 订单、商品、支付、物流、评价：可能是电商或零售。
- 事件、页面、会话、曝光、点击、留存：可能是互联网产品或内容平台。
- 贷款、授信、逾期、违约、还款：可能是金融风控。
- 注册、激活、渠道、活动、转化：可能是用户增长或运营。
- 实验、分组、variant、曝光、转化：可能是 A/B Test。
- 课程、学员、成绩、完课、续费：可能是教育。
- 岗位、候选人、投递、面试、offer：可能是招聘。
- 门店、SKU、库存、会员、促销：可能是零售经营。

## 如何避免强行套用电商模板

1. 不要在未确认 `order_id`、订单金额、支付状态等字段前使用 GMV。
2. 不要在未确认用户行为事件前使用 DAU、留存、漏斗。
3. 不要在未确认实验分组前使用 A/B Test 显著性。
4. 不要在未确认逾期或违约字段前使用坏账率、逾期率。
5. 所有指标必须能追溯到真实字段。

## 行业不明确时的处理

如果证据不足，请输出 2-3 个候选方向：

- 候选行业 / 场景
- 判断依据
- 缺失证据
- 适合包装的项目主题
- 需要用户确认的问题

## 用户确认项目主题

行业识别完成后，请让用户确认最终项目主题，例如：

```text
请确认项目主题：A. 用户增长分析 / B. 互联网产品留存分析 / C. 通用运营分析。
确认后我将调用对应 domain_pack，并继续生成业务分析框架和执行计划。
```

## 如何调用 domain_pack

1. 根据用户确认的行业，在 `domain_packs/` 中选择最匹配文件。
2. 如果没有完全匹配，使用 `domain_packs/通用数据分析.md`。
3. domain_pack 只作为分析方向参考，不能虚构字段和结论。

输出：

- `docs/行业识别报告.md`
