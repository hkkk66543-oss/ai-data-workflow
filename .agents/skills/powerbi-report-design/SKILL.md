# 按业务与数据设计 Power BI

统一设计质量标准，不统一所有项目的页面结构。不要复制本母版示例或历史测试集的行业、指标、页数、配色和布局。

## 先理解，再设计

读取已确认行业、业务问题、指标口径、本次成功 SQL 运行结果、字段元数据和 QA。检查时间跨度、类别数量、标签长度、数量级、正负值、空值、集中度及数据粒度。

在 `powerbi_notes/design_brief.md` 记录受众、核心决策、数据条件、各页问题、布局与图表选择依据。只放对该问题有用的组件；不规定四张卡、两张图或固定页数。缺少时间、上期、目标或事件顺序时，不补造同比、达成率、漏斗或结论。

## 视觉设计的共同底线

- 默认充分利用画布，不放装饰性深色侧栏、占位导航按钮或行业插画。优先使用底部页面标签；只有明确导航需求且可实际实现时才分配导航区域。
- 根据主题和受众选择主色，建立画布、内容表面、浅色分析分区、强调色和风险色的层次。避免近白画布叠加全白组件导致整页发平，也避免每张图随机换色。
- 根据业务含义给组件分配颜色角色；同一指标跨页一致。常规主色、次要指标色、正向色和风险色分开管理，不把上涨一律视为好事。
- 指标卡可以用低饱和背景配深色数字；分析图可用浅色分区或标题色标，密集表格优先保持中性表面。白色可以使用，但不作为所有组件的唯一背景。
- 字体层级、对齐、间距、圆角与数字格式一致；中文字体需在目标环境可用。不为装饰增加分区编号、眉题、粗边框、阴影和重复标题。
- 颜色不能独自承担状态含义；结合正负号、标签、零基线或状态文字。正负混合图按值表达，不能把正值和负值全部涂成风险红。

需要配色与配置示例时读取 [颜色与单位规则](references/color-and-units.md)。示例色值是起点，不能变成所有行业强制使用的主题。

## 根据数据安排空间

- 时间序列优先保证走势可读；减少刻度，默认不显示每个点的标签。更改日/周/月粒度须有明确口径，不擅自汇总。
- 长名称优先横向条形图并预留标签宽度；截断时保留完整名称查看途径。
- 排名明确排序指标与方向。Top N、其他合并和筛选范围必须说明，不能让子集卡片被当成全量。
- 一个主要分析区配必要的辅助内容；根据类别数与文字密度调整大小。完整明细按需单独成页，避免挤压趋势和排名图。
- 超出自动布局能力时使用 `manual` 并指定坐标，或拆页；不把组件压小塞满。没有必要的卡片或表格就省略。

## 单位与数字

依据真实数量级选择元、千、万、亿；指标卡把单位放在数字后，例如 `6,360.20 万`，标题使用“收入”。数量不大时保留原单位，不为统一外观一律缩放。

使用数值型 DAX 和格式字符串；金额除以 10000 后再追加“万”，不能把原金额仅改后缀，也不能用静态文字或 `FORMAT()` 文本结果替代可计算度量值。图表与明细可采用不同展示单位，但须明确标注并能对账；不改变币种、汇率或统计资格。

## 落到可执行工程

1. 在 `powerbi_notes/design_tokens.yaml` 保存颜色角色、字体、间距及各组件的选择依据；同时把可执行字段写入报表 YAML，不能只留在说明中。
2. 当前生成器使用 `design.palette`、`design.colors`；组件使用 `role`、`fill`、`color`、`show_labels`；度量值使用 `display_unit`。具体接口见 `docs/PowerBI设计升级说明.md`。
3. 自动布局只是位置辅助；行业、指标、页数、图表与语义颜色由本次业务及数据决定。
4. 保留真实字段绑定和数值型度量值。不支持的条件格式、复杂布局或交互，须扩展后验证或明确交接，不能仅在效果图中画出并声称工程已实现。

## 验收

生成 `powerbi_notes/design_review.md`：记录引用与结构检查、越界/重叠、标签密度、完整名称、颜色语义、数值缩放对账，以及 Desktop 实际截图检查结果。

检查实际应用的背景色和文字对比，不能把主题 JSON 写入成功当作显示成功。Desktop 打开、刷新、数值和交互尚未检查时保持 `desktop_validated: false`；区分样例图、静态检查与实际验收。

本 Skill 蒸馏了 Anthropic frontend-design 的主题身份、克制和截图自审，UI UX Pro Max 的语义样式与反面模式，以及 Microsoft Fabric Skills 的模型先行和报表工作流方法。仅采用设计原则，不复制品牌、商业模板或业务数据；来源链接见参考文件。
