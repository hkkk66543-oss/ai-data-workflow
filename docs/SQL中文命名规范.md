# SQL 中文命名规范

## 适用范围

本规范适用于项目生成的 MySQL 8.0 SQL 文件，包括 ODS、DWD、DIM、ADS 和 CHECKS 层。

## 默认策略

- 表名和字段名尽量使用简约明了的中文。
- 所有中文表名和中文字段名必须使用反引号包裹。
- 所有表和字段必须加中文注释。
- 所有指标字段必须先写业务口径，再写 SQL。
- 不允许凭空新增字段；所有字段必须能追溯到真实原始字段或明确加工逻辑。

## 表命名

| 分层 | 推荐格式 | 示例 |
|---|---|---|
| ODS 原始层 | `原始_对象表` | `原始_事件表`、`原始_订单表`、`原始_用户表` |
| DWD 清洗明细层 | `清洗_对象明细` | `清洗_事件明细`、`清洗_订单明细`、`清洗_用户画像` |
| DIM 维度层 | `维度_对象` | `维度_设备`、`维度_地区`、`维度_产品` |
| ADS 应用层 | `应用_分析主题` | `应用_每日概览`、`应用_用户分层`、`应用_渠道分析` |
| CHECK 校验层 | `校验_校验主题` | `校验_数据质量明细`、`校验_指标汇总` |

## 兼容方案

如果 MySQL 环境、BI 工具或团队规范不适合直接使用中文物理表名：

1. 物理表名和字段名使用简短英文。
2. 创建中文视图供 Navicat 和 Power BI 使用。
3. 保留 `docs/SQL中英文命名映射表.md`。
4. 在 SQL 文件头部说明采用兼容方案的原因。

## SQL 完成后必须说明

- 生成了哪些中文表。
- 每张中文表的业务含义。
- 每张表由哪些原始字段加工而来。
- 哪些字段是清洗字段。
- 哪些字段是异常标记字段。
- 哪些表适合导入 Power BI。
- 本次 SQL 自动执行入口、实际 MySQL 版本、校验结果和临时实例清理状态。
- 结果 CSV、建模字段、实际 DDL 和 SQL 源码的保存位置；执行流程见 [SQL 自动执行说明](SQL自动执行说明.md)。
