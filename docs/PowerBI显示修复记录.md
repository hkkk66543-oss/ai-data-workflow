# Power BI 显示修复记录

本文记录 2026-10-16 特定示例的修复与当时检查结果，不作为新项目的交付步骤。当前使用方法见 [自动生成说明](PowerBI自动生成说明.md) 和 [主题与布局说明](PowerBI设计升级说明.md)。

日期：2026-10-16。触发：用户在 Desktop 的蓝/绿页面截图显示日期出现小时刻度、列表筛选被截断、明细第三行被截断、部分文字较小。用户已确认上一版三套工程的刷新、数值和筛选联动通过；本次不修改 CSV、模型字段和指标口径。

## 实施

- 设计页面的筛选器显式使用 Dropdown，隐藏重复字段头，放大选项文字；预留 128px 高度。不再在短容器里显示可滚动列表。
- 对 date 类型的折线/柱状图明确设置 categoryAxis.axisType=Categorical，沿用字段 yyyy-MM-dd 格式。datetime 类型仍保留连续时间轴，不抹掉真实小时粒度。
- 重新分配 FHD 页面空间：双图+明细场景的指标卡从 144px 调整至 128px，分析图高 256px，明细表从 192px 增至 288px；对应分区标题同步移动。继续阻断重叠、越界和分析图高度小于 240px 的布局。
- 指标数值 40pt、图表标题 16pt、分类轴与数据标签 14pt、数值轴 12pt、表格表头/内容 14pt，说明与分区文字也放大。
- 原生组件显式写入关键格式，避免只依赖主题继承。关闭自动重复副标题，保留主题配色和表格自适应列宽。

3 套示例仍使用三行合成数据，未筛选时 3 / 60.50，A 为 2 / 30.50。数据校验和与上一版一致。

## 验证

- 全套 48 项测试：45 通过，3 项需 MYSQLD_PATH 的真实 MySQL 测试本轮跳过。新增回归测试覆盖实际生成的下拉模式、日期分类轴、表格最小高度、显式字号、无重复副标题、布局不重叠，以及 datetime 不被强制改成日期轴。
- 三套工程共 50 份 PBIP/PBIR JSON 通过官方 Schema；3 份主题通过官方主题 Schema。
- 三个模型均通过 Microsoft TOM 19.118.3 实际反序列化，各 1 表、4 字段、2 指标。
- 当前环境没有 Windows Power BI Desktop。本次是源码与结构检查通过，不能声称修复版已经完成 Desktop 显示验收。新工程仍标记 draft、desktop_validated=false；上一版通过的用户验证记录不替代本轮验证。

后续工程的实际显示与交互应分别记录验收结果；历史快照不自动更新新工程的 `desktop_validated` 状态。
