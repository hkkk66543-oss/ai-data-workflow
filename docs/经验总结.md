# 经验总结

## 通用十阶段工作流

### 第一阶段：Context / Data Understanding

目标：理解数据，而不是直接分析。

输出：

- `docs/数据字典.md`
- `docs/数据质量报告.md`
- `docs/表关系说明.md`

### 第二阶段：Domain Identification

目标：判断当前数据属于什么业务场景。

输出：

- `docs/行业识别报告.md`

行业识别报告必须包含：

1. 当前数据可能属于哪些行业。
2. 判断依据是什么。
3. 每个行业方向适合做什么项目。
4. 推荐的项目主题。
5. 需要用户确认的问题。

### 第三阶段：Brainstorming

目标：基于行业和真实数据，头脑风暴项目方向。

输出：

- `docs/项目选题建议.md`

### 第四阶段：Plan

目标：根据确认后的项目主题，拆解分析模块。

输出：

- `docs/业务分析框架.md`
- `docs/指标口径.md`

### 第五阶段：Work-Plan

目标：生成可执行任务清单。

输出：

- `docs/执行计划.md`

### 第六阶段：Execute

目标：生成 SQL、Python 数据质量与辅助校验、Power BI 方案、BI 样例图提示词、报告。

输出：

- `sql/`
- `scripts/`
- `outputs/`
- `powerbi_notes/`
- `README.md`

### 第七阶段：Test / Verify / QA

目标：校验数据、代码、指标、结论。

输出：

- `outputs/reports/qa_report.md`
- `sql/04_checks/check_all.sql`

### 第八阶段：Review

目标：审查项目是否适合放到简历和 GitHub。

输出：

- `outputs/reports/review_report.md`

### 第九阶段：Learn

目标：沉淀经验，更新提示词和规则。

输出：

- `docs/经验总结.md`
- `prompts/10_reuse.md`

### 第十阶段：Reuse

目标：让这套工作流可以复用到下一个行业项目。

输出：

- `prompts/00_master_prompt.md`

## 通用复盘规则

- 先记录行业识别是否准确。
- 再记录指标口径是否完全基于真实字段。
- 最后记录哪些 domain_pack 可复用、哪些需要更新。
